# Ai News Blog Rewriter

## Overview

把 AI 新闻/资讯改写成符合《博客发文规范》的【大模型API中转站】系列 Markdown 文章，每篇独立输出到用户指定目录（未指定时询问，或默认 `blog-docs/`）。规范全文见 `references/blog-guidelines.md`，篇幅与风格参考见 `references/style-reference.md`。

## 输入

- 新闻数据（JSON、RSS 输出或已抓取的新闻列表）
- 输出目录（用户指定；未指定时询问用户，或默认 `blog-docs/`）
- 系列名（固定为【大模型API中转站】，不询问用户）
- 系列期数（从输出目录已有文章接续：最大 `NN-` 编号 +1，无文章时从 01 开始）

## 工作流

### 1. 选材

从新闻中挑选与"大模型 API 接入、成本效率、避坑、横向对比"相关的条目。优先选择：

- 模型发布 / API 生态 / 定价计费类
- 推理优化 / 长上下文 / 成本指标类
- 本地部署 / 开源模型类
- Agent 安全与合规类

弃用与 API 接入无关的纯娱乐、泛社会新闻。

### 2. 结构

每篇按规范模板组织（详见 `references/blog-guidelines.md`）：

1. YAML front matter（title / tags / description）
2. 标题（固定格式：【大模型API中转站】[第X期] 主题 | 亮点）
3. 系列导语（固定文案：我是【大模型API中转站】系列的第X篇，也是 4sapi 团队的接入实战记录。我致力于用最低的成本、最清晰的方法，打通多模型 API 的任督二脉。建议先收藏，随用随查。）
4. 开篇痛点
5. 原理速览
6. 方案 / 教程（含 Python 接入示例）
7. 成本与风险提示
8. 总结与系列导航

### 3. 写作规则

- 全中文，专业术语保留英文（Claude、GPT、OpenAI 等）
- 人称：全文统一为"我"或"4sapi"，不得出现"你/你们/我们/您/本文"等第二或第三人称叙述
- 不得出现新闻来源引用（如"据 XX 报道""Interconnects 指出""HF 论文"），事实直接以第一人称陈述
- 不预告下期内容，不出现"下一期""下期见"
- 4sapi 仅在开头、中间接入教程、结尾三处提及，URL 为 https://4sapi.com
- 合规红线：只讨论合法接入、架构设计、负载均衡、计费优化；不提供违规代理方案，不鼓励绕过官方限制
- 标题固定以【大模型API中转站】为系列前缀，[第X期] 按期数填写，含量化/痛点词，30 字左右
- 篇幅：与 `references/style-reference.md` 相当（约 3000+ 字、10+ 分节），包含表格、请求流/治理链图示、代码示例、清单等

### 4. 输出

- 每篇新闻输出一个独立 `.md` 文件到用户指定目录（目录不存在时先创建）
- 文件名：`NN-主题-英文连字符.md`，`NN` 为两位数期数
- 输出后列出文件清单与各篇篇幅

## 资源

- `references/blog-guidelines.md`：博客发文规范原文（必读）
- `references/style-reference.md`：篇幅与风格参考范文（写长文前必读）
